## 本节目标

理解协程与事件循环，分清「并发」和「并行」，能用 `gather` 把多个 I/O 任务压到一起。

## 协程不是函数调用

```python
async def hello():
    return "hi"

hello()                 # <coroutine object>，函数体没有执行
await hello()           # 必须在 async 函数里
asyncio.run(hello())    # 程序入口
```

调用 `async def` 只创建协程对象，必须 `await` 或交给事件循环才会真正执行。

## 为什么 I/O 能并发

`await` 在等待 I/O 时把控制权交还事件循环，事件循环转去执行别的任务。所以：

- 网络、文件、数据库：适合异步
- 纯计算循环：异步没有帮助，GIL 仍然存在

**并发不等于并行**：单线程内快速切换任务，同一时刻仍然只有一个在跑。

## 串行 vs 并发

```python
# 串行：总耗时 = 各请求之和
results = []
for url in urls:
    results.append(await fetch(url))

# 并发：总耗时 ≈ 最慢的那个
results = await asyncio.gather(*(fetch(url) for url in urls))
```

`gather` 返回的顺序**与传入顺序一致**，不是完成顺序。

## 异常与取消

`gather` 默认遇到第一个异常就向上抛。想让所有任务跑完再统一处理：

```python
results = await asyncio.gather(*tasks, return_exceptions=True)
```

此时异常对象会作为结果返回，由调用方判断。

## 练习

实现 `fetch_all(urls, fetch)`：

- `fetch` 是异步函数，`await fetch(url)` 返回字符串
- 并发执行所有请求
- 返回顺序与 `urls` 一致
- 任一请求抛异常，向上传播
- 空列表返回 `[]`

## 检查点

测试注入的 fetch 带固定延迟，并测量总耗时。写成串行循环会超时失败。
