## 最小异步请求

```python
import asyncio
import httpx

async def fetch(url: str) -> str:
    async with httpx.AsyncClient(timeout=5.0) as client:
        response = await client.get(url)
        response.raise_for_status()
        return response.text
```

`raise_for_status()` 把 4xx/5xx 转成 `httpx.HTTPStatusError`。不调用它，你会把错误页当成成功结果。

## 生产配置

```python
limits = httpx.Limits(max_connections=20, max_keepalive_connections=10)
timeout = httpx.Timeout(5.0, connect=2.0)
headers = {"User-Agent": "my-crawler/0.1 (+contact@example.com)"}

async with httpx.AsyncClient(limits=limits, timeout=timeout, headers=headers) as client:
    ...
```

一个 Client 复用连接，不要每次请求都新建。反复建 Client 等于放弃连接池。

## 本地模拟服务

先用标准库起一个可控服务，不要拿真实网站做实验：

```python
# mock_server.py
import time
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path.startswith("/slow"):
            time.sleep(0.5)
        if self.path.startswith("/error"):
            self.send_response(500)
            self.send_header("Content-Length", "0")
            self.end_headers()
            return
        body = b"ok"
        self.send_response(200)
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

    def log_message(self, *args):
        pass

if __name__ == "__main__":
    ThreadingHTTPServer(("127.0.0.1", 8000), Handler).serve_forever()
```

运行 `python mock_server.py`，然后抓 `http://127.0.0.1:8000/`、`/slow`、`/error`。

`ThreadingHTTPServer` 每连接一个线程，所以能真实测出并发差异。

## 把模拟服务换成真实客户端

前面练习里的 `fetch` 是注入参数。换实现时，编排代码一行都不用改：

```python
# 测试里：确定性替身
results = await fetch_limited(urls, mock_service.fetch, limit=3)

# 生产里：真实 HTTP
client = httpx.AsyncClient(timeout=5.0)

async def fetch(url):
    response = await client.get(url)
    response.raise_for_status()
    return response.text

results = await fetch_limited(urls, fetch, limit=3)
```

这就是依赖注入的价值：测试用可控替身，生产用真实实现，中间的业务逻辑只写一遍。

## 抓取礼仪与边界

- 先看 `robots.txt`，遵守 Crawl-delay
- 单域名并发压到 2–5，不要用 50 并发打小站
- 设置可识别的 User-Agent 和联系方式
- 只对幂等请求重试（GET 可以，POST 不一定）
- 处理 429：读 `Retry-After`，做指数退避
- 不抓登录态数据与个人隐私数据

## 本机自查

1. 启动 `mock_server.py`
2. 用 `httpx.AsyncClient` 并发抓 10 次 `/`，总耗时接近单次请求
3. 抓 10 次 `/slow`，把并发限制为 3，总耗时约为 0.5 秒 × 4 轮
4. 抓 `/error`，确认 `raise_for_status()` 抛错并被你的批量逻辑隔离
5. 把第 2–4 步套进 4.4 的 `crawl`，验证 attempts 与 error 字段符合预期
