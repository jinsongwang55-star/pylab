## 本节目标

搞清属性访问的底层协议，能手写一个带校验的数据描述符。这是 ORM、表单库、配置系统的共同基础。

## 属性访问走哪条路

`obj.attr` 的查找顺序：

1. 类型上的**数据描述符**（同时定义 `__get__` 和 `__set__`）
2. 实例的 `__dict__`
3. 类型上的非数据描述符或普通类属性

数据描述符优先级最高，这正是 `property` 能拦截赋值的原因。

## 三个方法

```python
class Descriptor:
    def __set_name__(self, owner, name):
        self.name = name          # 类创建时调用一次

    def __get__(self, instance, owner):
        if instance is None:
            return self           # 通过类访问
        return instance.__dict__.get(self.name)

    def __set__(self, instance, value):
        instance.__dict__[self.name] = value
```

- `__set_name__`：Python 3.6+，自动拿到属性名，不用手写字符串
- `__get__`：`instance is None` 表示通过类访问，通常返回描述符自身
- `__set__`：赋值时调用

## property 就是描述符

```python
class A:
    @property
    def x(self):
        return self._x
```

`property` 本身就是一个实现了 `__get__` / `__set__` 的类。你手写的描述符只是更通用、可复用的版本。

## 复用校验逻辑

```python
class Positive:
    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, instance, owner):
        if instance is None:
            return self
        return instance.__dict__[self.name]

    def __set__(self, instance, value):
        if value <= 0:
            raise ValueError(f"{self.name} 必须大于 0")
        instance.__dict__[self.name] = value

class Product:
    price = Positive()
    stock = Positive()
```

一个描述符类可以同时服务多个字段，校验逻辑只写一次。

## 常见错误

| 错误 | 后果 |
|---|---|
| 值存在类属性上 | 所有实例共享同一份数据 |
| 忘记处理 `instance is None` | `Product.price` 直接崩 |
| 用 `self.name` 前没实现 `__set_name__` | AttributeError |
| 只实现 `__get__` | 变成非数据描述符，会被实例字典覆盖 |

## 练习

实现 `Positive` 描述符：

- `__set_name__` 记录属性名
- 通过类访问返回描述符自身
- 通过实例访问返回已存的值；未赋值抛 `AttributeError`，消息含属性名
- `__set__` 只接受 int 或 float（排除 bool），且必须大于 0，否则抛 `ValueError`，消息含属性名
- 值存在实例的 `__dict__` 中，多个实例互不影响

## 检查点

测试会检查类访问、实例隔离、未赋值、bool 拒绝，以及错误消息里的字段名。
