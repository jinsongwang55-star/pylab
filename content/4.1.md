## 本节目标

用 `asyncio.Semaphore` 控制同时在飞的请求数。抓一万个 URL 时，不限并发会打爆对方服务，也会耗光本机文件描述符。

## 为什么必须有上限

`gather` 会一次性创建所有任务。一万个连接同时打开：

- 对方返回 429 或直接封 IP
- 本机报 `Too many open files`
- 内存与调度开销飙升

## Semaphore

```python
sem = asyncio.Semaphore(10)

async def one(url):
    async with sem:
        return await fetch(url)

results = await asyncio.gather(*(one(u) for u in urls))
```

信号量内部有计数：进入减一，离开加一，计数为零时后来的任务排队等待。

## 限流与连接池的区别

- Semaphore 控制**业务层并发**，与客户端无关
- httpx 的 `Limits(max_connections=...)` 控制**连接池**
- 两者都要设，数量级要匹配

## 常见错误

| 错误 | 后果 |
|---|---|
| 在 `async with sem` 外面 await fetch | 限流失效 |
| 每个任务创建一个 Semaphore | 等于没限制 |
| limit 设为 0 | 所有任务永久阻塞 |

## 练习

实现 `fetch_limited(urls, fetch, limit)`：并发抓取，任何时刻进行中的请求不超过 `limit`，返回顺序与输入一致。

## 检查点

测试在 fetch 内部统计并发峰值，`limit=3` 时峰值必须 ≤ 3；还会用 `limit=1` 验证退化为串行。
