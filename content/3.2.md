## 本节目标

把「今天」作为参数传入，而不是在函数内部读系统时间。这一步决定了业务逻辑能不能被稳定测试。

## 隐藏依赖的问题

```python
from datetime import date

def is_expired(due: date) -> bool:
    return due < date.today()
```

这段代码看起来没问题，但：

- 测试结果随运行日期变化，今天过、明天失败
- 无法测试「边界当天算不算过期」
- 无法模拟跨年、闰日

## 纯函数

同样的输入永远得到同样的输出，不读写外部状态。把时间变成参数：

```python
def is_expired(due: date, today: date) -> bool:
    return due < today
```

测试时传固定日期：

```python
assert is_expired(date(2026, 11, 1), date(2026, 11, 9)) is True
assert is_expired(date(2026, 11, 9), date(2026, 11, 9)) is False
```

这就是「依赖注入」的最简单形态：不注入类、不引入框架，只是**把依赖变成参数**。

## 业务规则写进函数

```python
def overdue_days(due: date, today: date) -> int:
    if due >= today:
        return 0
    return (today - due).days
```

边界写清楚：未过期返回 0，当天算未过期。这类规则必须由测试钉死，而不是靠注释。

## 解析与业务分离

```python
def build_summary(tasks: list[dict], today: date) -> dict:
    ...
    due = date.fromisoformat(task["due"])
```

解析字符串、计算、组装结果分成清晰的几步。哪天要换日期格式，只需要改解析那一行。

## 练习

实现三个函数：

- `is_expired(due, today)`：`due` 早于 `today` 返回 True，相等不算过期
- `overdue_days(due, today)`：已过期返回相差天数，未过期返回 0
- `build_summary(tasks, today)`：`tasks` 元素形如 `{"title": str, "due": "YYYY-MM-DD"}`，返回 `{"total": int, "overdue": int, "overdue_titles": list[str]}`，标题保持输入顺序

## 检查点

测试固定传入 `date(2026, 11, 9)`。你的函数里只要出现 `date.today()`，在不同日期跑就会得到不同结果，等于给自己埋雷。
