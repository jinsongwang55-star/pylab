## 本节目标

给每个请求加超时，并让单个失败不影响整批结果。

## 没有超时的后果

一个挂起的连接会让整批任务永远等下去。`asyncio.gather` 不会自动超时。

## wait_for

```python
try:
    result = await asyncio.wait_for(fetch(url), timeout=3)
except asyncio.TimeoutError:
    result = None
```

`wait_for` 超时会取消内部协程。Python 3.11+ 也可以写 `async with asyncio.timeout(3):`，但 `wait_for` 兼容性更好。

## 失败隔离

批量任务里，一个 500 或 DNS 失败不应该让其余结果全丢：

```python
async def one(url):
    try:
        return await asyncio.wait_for(fetch(url), timeout=3)
    except Exception:
        return None

results = await asyncio.gather(*(one(u) for u in urls))
```

这里的 `except Exception` 是合理的：在批量任务边界把异常转成可展示的结果。但**只捕获不记录等于埋雷**，真实项目里必须同时写日志。

## 超时值怎么定

- 连接超时短（1–2 秒），读取超时可长一些
- 客户端超时必须小于上游调用方的超时，否则上游先断，日志对不上

## 练习

实现两个函数：

- `fetch_with_timeout(url, fetch, seconds)`：超时返回 `None`
- `collect(urls, fetch, seconds)`：并发抓取，单请求超时或其他异常都返回 `None`，顺序与输入一致

## 检查点

测试会用一个「永远挂起」的模拟 URL，验证你确实提前返回，而不是等它自然结束。
