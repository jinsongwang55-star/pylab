## 本节目标

不借助框架，把路由、校验、鉴权拼成一个能处理四个端点的迷你 API。这是阶段 5 的收官。

## 接口契约

| 方法 | 路径 | 说明 | 成功状态码 |
|---|---|---|---|
| POST | /users | 注册 | 201 |
| POST | /login | 登录拿 token | 200 |
| GET | /posts | 文章列表（新→旧） | 200 |
| POST | /posts | 发文，需要 Bearer token | 201 |

## 数据结构

```python
db = {"users": [], "posts": []}
```

- user：`{"id", "username", "password_hash"}`
- post：`{"id", "author_id", "title", "content"}`

## 状态码规则

| 情况 | 状态码 |
|---|---|
| 请求体字段不合法 | 400 |
| 用户名已存在 | 409 |
| 用户名或密码错误 | 401 |
| 缺少或无效 token | 401 |
| 路径不存在 | 404 |
| 路径存在但方法不对 | 405 |

401 与 403 的区别：401 是「不知道你是谁」，403 是「知道你是谁，但你没权限」。

## 鉴权头

```
Authorization: Bearer <token>
```

先判断前缀，再取后面部分。不要用 `split(" ")[1]`，多个空格会崩。

## 实现要点

- 注册：校验 → 查重 → 哈希 → 追加 → 返回
- 登录：查用户 → 验证密码 → 发 token；用户不存在与密码错误返回同样的信息，避免账号枚举
- 发文：先鉴权再校验 body；顺序反了会泄露「未登录也能探测字段规则」
- 列表：`reversed(posts)`，返回副本而不是内部对象

## 练习

实现 `handle_request(method, path, body, *, secret, db, headers=None)`，返回 `(status, payload)`。

起始代码已提供 `hash_password`、`verify_password`、`make_token`、`verify_token`，你只写 HTTP 层。

## 检查点

测试覆盖：注册、重复注册、非法 body、登录成功/失败、无 token 发文、正常发文与列表顺序、404/405。
