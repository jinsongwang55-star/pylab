## 本节目标

理解类本身也是对象，能被「创建类的类」控制。知道它什么时候有用，以及什么时候该用更简单的 `__init_subclass__`。

## 类也是对象

```python
class A:
    pass

print(type(A))          # <class 'type'>
B = type("B", (), {})   # 等价于 class B: pass
```

`type` 是默认的元类：接收「类名、基类元组、命名空间」来创建类。

## 自定义元类

```python
class RegistryMeta(type):
    registry = {}

    def __new__(mcls, name, bases, namespace):
        cls = super().__new__(mcls, name, bases, namespace)
        if bases:                      # 跳过根基类
            key = getattr(cls, "key", None)
            if not key:
                raise TypeError(f"{name} 必须定义 key")
            if key in mcls.registry:
                raise ValueError(f"重复的 key: {key}")
            mcls.registry[key] = cls
        return cls

class Plugin(metaclass=RegistryMeta):
    key = ""

class JsonPlugin(Plugin):
    key = "json"
```

子类创建时自动注册，调用方不需要维护映射表。

## 更轻的替代：__init_subclass__

```python
class Plugin:
    registry = {}

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Plugin.registry[cls.key] = cls
```

大多数「注册子类」的需求，用这个钩子就够了，不需要元类。

## 什么时候真的需要元类

- 要在**类创建之前**修改命名空间（自动收集字段、改写方法）
- 要实现 `__call__` 改变实例化行为
- 框架层需要强制约束所有子类

业务代码几乎不需要。元类会让继承、调试、类型检查都变复杂。能用 `__init_subclass__` 或类装饰器，就别用元类。

## 常见错误

| 错误 | 后果 |
|---|---|
| 忘记 `super().__new__` | 类根本没被创建 |
| 在元类里做耗时 I/O | 每次导入都变慢 |
| 用元类实现本可以用装饰器的功能 | 无谓的复杂度 |

## 练习

实现 `PluginMeta` 与根基类 `Plugin`：

- 元类维护 `registry` 字典
- 子类必须定义非空字符串 `key`，否则在类创建时抛 `TypeError`
- `key` 重复抛 `ValueError`
- 子类创建后自动进入 `registry`
- 根基类本身不注册

## 检查点

测试会在函数内部动态定义类，验证注册、重复、缺失 key，以及元类类型。
