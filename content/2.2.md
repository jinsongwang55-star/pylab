## 本节目标

用 `logging` 替代 `print`，并搞清 logger / handler / formatter 的关系——这是配置日志时反复踩坑的根源。

## 为什么不用 print

- 无法分级过滤（调试信息混在生产错误里）
- 无法同时输出到控制台和文件
- 没有时间戳和来源模块
- 上线后关不掉

## 三个对象

| 对象 | 职责 |
|---|---|
| Logger | 接收日志调用，按级别决定是否放行 |
| Handler | 决定写到哪里（控制台、文件、网络） |
| Formatter | 决定日志长什么样 |

```python
import logging

logger = logging.getLogger("task")
logger.setLevel(logging.DEBUG)

handler = logging.FileHandler("app.log", encoding="utf-8")
handler.setLevel(logging.DEBUG)
handler.setFormatter(logging.Formatter("%(levelname)s|%(message)s"))

logger.addHandler(handler)
logger.info("开始处理")
```

一条日志要过 **logger 级别 → handler 级别** 两道闸门，任意一道不通过就不会输出。这是「明明设了 DEBUG 却没日志」的头号原因。

## propagate

子 logger 默认把日志向上级 logger 传递。如果父 logger 也挂了 handler，同一条日志会打印两次。库代码通常设置：

```python
logger.propagate = False
```

## 重复配置的坑

```python
def setup():
    logger = logging.getLogger("task")
    logger.addHandler(logging.StreamHandler())   # 每次调用都加一个
    return logger

setup()
setup()
# 现在有 2 个 handler，每条日志打印两次
```

正确做法：配置前 `logger.handlers.clear()`，或检测到已配置就直接复用。

## 练习

实现 `setup_logger(log_path, verbose=False)`：

- logger 名为 `task`，`propagate = False`，级别 `DEBUG`
- 文件 handler：DEBUG 起，格式 `"%(levelname)s|%(message)s"`
- 控制台 handler：写 **stdout**，`verbose=True` 时 DEBUG 起，否则 INFO 起，格式 `"%(message)s"`
- 每次调用先清空旧 handler，重复调用不会叠加

## 检查点

测试会连续调用两次，检查 handler 数量恒为 2，并确认旧文件不再收到新日志。
