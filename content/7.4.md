## 本节目标

用描述符收集字段、用元类收集元数据，实现一个迷你 ORM 的模型层。这就是 Django Model 与 SQLAlchemy 声明式映射的核心思路。

## 目标用法

```python
class User(Model):
    name = Field(str)
    age = Field(int)
    nickname = Field(str, default="匿名")

user = User(name="alice", age=30)
user.to_dict()          # {"name": "alice", "age": 30, "nickname": "匿名"}
User.from_dict({"name": "bob", "age": 20})
```

## 三个角色

| 组件 | 职责 |
|---|---|
| `Field` 描述符 | 单个字段的存取与类型校验 |
| `ModelMeta` 元类 | 类创建时收集所有 Field 到 `_fields` |
| `Model` 基类 | 初始化、序列化、反序列化 |

## 收集顺序

`_fields` 必须保持定义顺序，`to_dict` 的输出才稳定。Python 3.7+ 的类命名空间是插入有序的，直接遍历 `namespace` 即可。

继承时先合并基类字段，再覆盖子类字段：

```python
fields = {}
for base in bases:
    fields.update(getattr(base, "_fields", {}))
fields.update({k: v for k, v in namespace.items() if isinstance(v, Field)})
```

## 类型校验

```python
def __set__(self, instance, value):
    if value is not None:
        if self.type is int and isinstance(value, bool):
            raise TypeError("age 不能是 bool")
        if not isinstance(value, self.type):
            raise TypeError("类型不匹配")
    instance.__dict__[self.name] = value
```

bool 是 int 的子类，不额外判断就会让 `age=True` 通过。

## 字段值为什么不能存在描述符上

描述符是类属性，所有实例共享同一个对象。值必须写进 `instance.__dict__`，才能按实例隔离。

## 检查点

测试覆盖字段收集顺序、类访问、默认值、类型校验、bool 拒绝、未知字段、序列化与反序列化、实例隔离。

## 练习

实现 `Field`、`ModelMeta`、`Model`：

- 类访问 `User.name` 返回 Field 对象
- 实例访问返回自己的值；未传参时使用默认值
- 类型不符抛 `TypeError`；int 字段拒绝 bool
- 未知字段抛 `TypeError`
- `to_dict` 按字段定义顺序返回字典
- `from_dict` 构造实例
