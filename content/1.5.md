## 本节目标

理解迭代协议，会用 `yield` 写生成器，并说清它到底省在哪。

## 迭代协议

`for` 循环背后是两次调用：

```python
numbers = [1, 2, 3]
it = iter(numbers)     # 得到迭代器
next(it)               # 1
next(it)               # 2
next(it)               # 3
next(it)               # StopIteration
```

任何实现了 `__iter__` 与 `__next__` 的对象都能被 `for` 消费。

## yield

含 `yield` 的函数，调用时**不执行函数体**，而是返回一个生成器。每次 `next()` 执行到下一个 `yield` 就暂停并交出一个值，下次从暂停处继续。

```python
def countdown(n):
    while n > 0:
        yield n
        n -= 1

g = countdown(3)
next(g)     # 3
next(g)     # 2
next(g)     # 1
next(g)     # StopIteration
```

**关键差异**：`return` 结束函数并交出一个值；`yield` 暂停函数并交出一个值，之后还能继续。

## 内存差别

```python
squares_list = [x * x for x in range(10_000_000)]    # 立刻占用几百 MB
squares_gen  = (x * x for x in range(10_000_000))    # 几乎不占内存
```

生成器表达式只在上游要值时才算一个。流式处理大数据时优先用生成器，但注意它只能遍历一次。

## 无限序列

生成器可以表示无限序列，因为它惰性：

```python
def fib():
    a, b = 0, 1
    while True:
        yield a
        a, b = b, a + b
```

序列永不结束，取多少由调用方决定。

## 练习

实现两个函数：

- `fib()`：无限生成器，依次产出 `0, 1, 1, 2, 3, 5, 8, ...`
- `take(iterable, n)`：取前 `n` 个元素组成列表；不足 `n` 个时返回已有的全部

## 检查点

测试用 `inspect.isgenerator` 确认 `fib()` 真的是生成器。如果写成返回列表的普通函数，第一项就会失败。
