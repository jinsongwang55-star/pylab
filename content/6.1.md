## 本节目标

把「在我机器上能跑」变成「在任何机器上都一样跑」。核心产物是一个可复现的镜像。

## 镜像解决什么

| 问题 | 容器给出的答案 |
|---|---|
| 服务器 Python 版本不同 | 镜像自带解释器 |
| 系统依赖缺失 | 镜像里装好 |
| 依赖版本漂移 | 锁文件 + 镜像层固化 |
| 换机器要重配 | `docker run` 一条命令 |

## 多阶段 Dockerfile

```dockerfile
# ---- 构建阶段：只负责装依赖 ----
FROM python:3.12-slim AS builder

WORKDIR /app
COPY pyproject.toml uv.lock ./
RUN pip install --no-cache-dir uv \
 && uv sync --frozen --no-dev

# ---- 运行阶段：只带运行必需的东西 ----
FROM python:3.12-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    PATH="/app/.venv/bin:$PATH"

WORKDIR /app
RUN useradd --create-home --uid 10001 appuser

COPY --from=builder /app/.venv /app/.venv
COPY app ./app

USER appuser
EXPOSE 8000

HEALTHCHECK --interval=10s --timeout=3s --retries=5 \
  CMD python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health')"

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "2"]
```

几个关键点：

- **先拷贝依赖声明再装依赖**，这样改业务代码不会让依赖层缓存失效
- **多阶段**让最终的镜像不含构建工具与缓存
- **非 root 用户**运行，容器逃逸的影响面小得多
- `PYTHONUNBUFFERED=1` 让日志立刻输出，否则 `docker logs` 会延迟
- `HEALTHCHECK` 用标准库 urllib，不依赖镜像里有没有 curl
- 需要项目提供 `GET /health` 返回 200

如果不用 uv，把构建阶段换成：

```dockerfile
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
```

## .dockerignore

```
.venv
__pycache__
*.pyc
.git
.env
data
tests
*.md
```

不忽略 `.env`，密钥就会被打进镜像层，之后无法彻底删除。

## 构建与运行

```bash
docker build -t blog-api:0.1 .
docker run --rm -p 8000:8000 --env-file .env blog-api:0.1
docker logs -f <容器ID>
docker exec -it <容器ID> sh
docker image ls blog-api
```

## 镜像体积与漏洞

```bash
docker image ls
docker scout quickview blog-api:0.1   # 有 Docker Scout 时
```

常见优化：

- 用 `-slim` 或 `alpine` 基础镜像（alpine 的 musl 可能与某些轮子不兼容）
- 不在最终镜像里放编译器和头文件
- 定期重建基础镜像，拿到安全补丁

## 常见错误

| 错误 | 后果 |
|---|---|
| `COPY . .` 放在装依赖之前 | 每次改代码都重装依赖，构建极慢 |
| 用 root 运行 | 一旦被突破，权限过大 |
| 把 `.env` 打进镜像 | 密钥泄露且无法真正删除 |
| 用 `latest` 标签部署 | 无法确定线上到底是哪个版本 |
| 不设 `HEALTHCHECK` | 容器进程活着但服务已经不可用 |
