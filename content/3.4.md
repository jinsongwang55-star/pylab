## 本节目标

实现一个可配置的重试策略，并理解「把副作用作为参数注入」为什么是可测试性的核心。

## 朴素写法

```python
import time

def retry(operation, attempts=3, delay=1.0):
    for _ in range(attempts - 1):
        try:
            return operation()
        except Exception:
            time.sleep(delay)
    return operation()
```

问题：测试它必须真的等待两秒。测试一慢，人就不愿意跑；不跑，测试等于不存在。

## 注入 sleep

```python
import time

class RetryPolicy:
    def __init__(self, attempts=3, delay=1.0, sleep=time.sleep):
        self.attempts = attempts
        self.delay = delay
        self.sleep = sleep

    def run(self, operation):
        for attempt in range(self.attempts):
            try:
                return operation()
            except Exception:
                if attempt == self.attempts - 1:
                    raise
                self.sleep(self.delay)
```

测试时传假的 sleep：

```python
delays = []
policy = RetryPolicy(attempts=3, delay=0.5, sleep=delays.append)
```

生产用默认值，测试用替身。默认参数指向真实实现，是依赖注入最轻的形态。

## 什么时候该重试

- 网络抖动、临时限流：适合
- 参数错误、认证失败：重试一万次也没用
- 非幂等操作（转账）：重试可能导致重复扣款

重试只适用于**可恢复且幂等**的失败。

## 异常信息不能丢

最终要抛出**最后一次**的真实异常，而不是笼统的 `RuntimeError("重试失败")`，否则问题现场全丢了。

## 练习

补全 `RetryPolicy.run(operation)`：

- 最多尝试 `attempts` 次
- 成功立即返回结果
- 失败后先调用 `self.sleep(self.delay)` 再重试
- 最后一次仍失败时，抛出最后一次的异常
- `attempts=1` 时只调用一次，不 sleep

## 检查点

测试会注入一个记录器当 sleep，断言调用次数与延迟序列。不要在里面直接写 `time.sleep`。
