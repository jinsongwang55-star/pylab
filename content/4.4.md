## 本节目标

把并发上限、超时、重试、结果汇总组合成一个可用的批量抓取函数。

## 结果结构

每个 URL 对应一条记录：

```python
{
    "url": "https://example.com/a",
    "ok": True,
    "body": "...",
    "error": "",
    "attempts": 1,
}
```

失败时 `ok=False`、`body=""`、`error` 是异常类名（超时为 `"TimeoutError"`）。批量任务的边界**永远不向外抛异常**，失败必须变成数据。

## 重试放在哪

```python
for _ in range(retries + 1):
    async with semaphore:
        try:
            body = await asyncio.wait_for(fetch(url), timeout)
            return success
        except ...:
            continue
```

信号量要包住**每一次尝试**，而不是整个重试循环。否则一个慢 URL 会长期占着名额，其他任务排队。

## 重试的代价

- 只重试可恢复错误（超时、连接失败、5xx）
- 4xx 通常不该重试
- 真实项目要加退避：`await asyncio.sleep(2 ** attempt)`
- 重试会放大流量，`retries=2` 意味着最坏 3 倍请求

## 练习

实现 `crawl(urls, fetch, *, limit=5, timeout=1.0, retries=2)`：

- 并发上限 `limit`
- 单次尝试超时 `timeout`
- 最多尝试 `retries + 1` 次
- 返回顺序与 `urls` 一致
- 永不抛异常

## 检查点

测试覆盖：全部成功、两次失败后成功、始终失败、永远挂起、并发峰值、空列表。
