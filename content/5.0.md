## 本节目标

理解 REST 路由的本质：把「方法 + 路径」映射到处理函数，并从路径中提取参数。

## HTTP 方法与语义

| 方法 | 语义 | 幂等 |
|---|---|---|
| GET | 读取 | 是 |
| POST | 创建 | 否 |
| PUT | 整体替换 | 是 |
| PATCH | 部分更新 | 否 |
| DELETE | 删除 | 是 |

「幂等」指重复执行的结果相同。GET 可以安全重试，POST 不行。

## 路径参数

```
GET /posts            列表
GET /posts/42         详情
GET /posts/42/comments
```

`42` 是路径参数。框架负责从 URL 里切出来，作为参数传给处理函数。注意它永远是**字符串**，需要自己转成 int。

## 路由顺序陷阱

```python
router.add("GET", "/posts/latest", handler_latest)
router.add("GET", "/posts/{id}", handler_detail)
```

静态路由必须放在动态路由前面，否则 `/posts/latest` 会被 `{id}` 捕获。这是 Web 框架里最常见的路由 bug。

## 404 与 405

- 路径不存在 → 404 Not Found
- 路径存在但方法不支持 → 405 Method Not Allowed

要区分这两者，路由器必须**先按路径匹配，再检查方法**。

## 练习

实现一个 `Router`：

```python
router = Router()
router.add("GET", "/posts/{post_id}", handler)
status, body = router.dispatch("GET", "/posts/42")
```

规则：

- 模式按 `/` 分段，`{name}` 匹配任意一段，并作为关键字参数传给 handler
- 匹配成功返回 `(200, handler(**params))`
- 路径存在但方法不符返回 `(405, {"error": "Method Not Allowed"})`
- 完全无匹配返回 `(404, {"error": "Not Found"})`
- 路径段数必须完全一致，不做前缀匹配

## 检查点

测试覆盖静态路由、单参数、多参数、404、405，以及 `/posts/42/extra` 不能被 `/posts/{id}` 误匹配。
