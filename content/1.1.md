## 本节目标

搞清 Python 的数值类型，以及为什么涉及金额时必须用 `Decimal`。

## 变量与类型

Python 的变量是名字绑定到对象，不是装值的盒子。类型属于对象，不属于变量。

```python
x = 35            # int
x = "35"          # 现在绑定到 str，完全合法
print(type(x))    # <class 'str'>
```

常用类型：

| 类型 | 字面量 | 说明 |
|---|---|---|
| int | `42` | 整数，任意精度，不会溢出 |
| float | `3.14` | 双精度浮点，存在表示误差 |
| bool | `True` | 布尔值，是 int 的子类 |
| str | `"abc"` | 不可变文本 |
| NoneType | `None` | 表示"没有值" |

判断类型用 `isinstance(x, int)`，它支持子类；`type(x) == int` 不支持。

## float 的问题

```python
>>> 0.1 + 0.2
0.30000000000000004
>>> 0.1 + 0.2 == 0.3
False
```

原因：float 是二进制浮点数，0.1 在二进制中是无限循环小数，只能截断存储。这不是 Python 的 bug，是 IEEE 754 的普遍行为。

涉及金额、计数、任何不能接受误差的场景，用 `decimal.Decimal`：

```python
from decimal import Decimal, ROUND_HALF_UP

price = Decimal("35.5")          # 从字符串构造
print(price)                      # 35.5
print(price.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))   # 35.50
```

**关键**：`Decimal(0.1)` 会把 float 的误差原样带进来，`Decimal("0.1")` 才是精确的。

## 舍入模式

`quantize` 决定多余位数怎么处理：

| 模式 | 0.005 变成 | 说明 |
|---|---|---|
| ROUND_HALF_UP | 0.01 | 四舍五入，财务常用 |
| ROUND_HALF_EVEN | 0.00 | 银行家舍入，Python 默认 |
| ROUND_DOWN | 0.00 | 直接截断 |

## 练习

实现 `parse_amount(raw)`：

- 把字符串转成 `Decimal`
- 非法输入（`"abc"`、空串）抛 `ValueError`
- 非有限值（`"NaN"`、`"Infinity"`）抛 `ValueError`
- 小于等于 0 抛 `ValueError`
- 合法值按 `ROUND_HALF_UP` 保留两位小数

提示：`Decimal("abc")` 抛的是 `decimal.InvalidOperation`，它不是 `ValueError` 的子类，需要自己转换。
