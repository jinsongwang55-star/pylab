## 本节目标

用异常表达失败，用上下文管理器保证资源与数据安全。

## 异常的基本结构

```python
try:
    value = int(raw)
except ValueError as exc:
    print(f"转换失败: {exc}")
except (TypeError, KeyError):
    print("另一种失败")
else:
    print("没出错才执行")
finally:
    print("无论如何都执行")
```

顺序固定：`except` → `else` → `finally`。

## 不要吞异常

```python
try:
    do_something()
except Exception:
    pass          # 错误写法：问题被永久隐藏
```

要么处理，要么让它冒泡。需要记录时用 `logging.exception()`，它会保留完整堆栈。

## 自定义异常

```python
class LedgerError(Exception):
    """记账业务异常基类。"""

class InvalidAmountError(LedgerError):
    """金额不合法。"""
```

好处是调用方能精确捕获业务错误，而不是靠错误信息字符串匹配。自定义异常继承 `Exception`，不要继承 `BaseException`。

## 上下文管理器

`with` 背后是两个方法：

```python
with open("a.txt") as fh:
    ...
```

等价于调用 `__enter__`，执行代码块，再调用 `__exit__`。即使块内抛异常，`__exit__` 也一定执行，所以文件一定关闭。

手写一个：

```python
import time

class Timer:
    def __enter__(self):
        self.start = time.perf_counter()
        return self
    def __exit__(self, exc_type, exc, tb):
        self.elapsed = time.perf_counter() - self.start
        return False        # 返回 False 表示不吞异常
```

## contextmanager 装饰器

多数情况下 `@contextmanager` 更简洁：

```python
from contextlib import contextmanager

@contextmanager
def tag(name):
    print(f"<{name}>")
    yield
    print(f"</{name}>")
```

`yield` 之前的代码相当于 `__enter__`，之后相当于 `__exit__`。**块内抛异常时，`yield` 之后的代码不会执行**——这正是让「写盘只在成功时发生」的机制。

## 练习

实现 `atomic_json(path, default)` 上下文管理器：

- 进入时读取 JSON；文件不存在则使用 `default` 的**深拷贝**
- `with` 块正常结束后原子写回（先写 `.tmp`，再 `os.replace`）
- 块内抛异常时**不写盘**，原文件内容保持不变
- `yield` 出可修改的数据（列表或字典）

## 检查点

测试会故意在 `with` 块里抛 `RuntimeError`，然后检查原文件是否一字未变。这是数据安全的核心验收点。
