## 本节目标

学会先测量再优化，掌握三个基本工具：`timeit`、`cProfile`、`tracemalloc`。

## 先测量，再动手

没有测量的优化，九成是浪费时间。先回答三个问题：

1. 慢在哪一段？
2. 它占总时间多少比例？
3. 改完快了多少？

## timeit：微基准

```python
import timeit

print(timeit.timeit("sum(range(100))", number=10_000))
print(timeit.timeit(lambda: [x * 2 for x in range(100)], number=10_000))
```

注意：

- 多跑几次，看数量级而不是小数点
- 不要把 I/O 放进 timeit
- 关掉调试日志再测

## cProfile：找热点

```bash
python -m cProfile -s cumtime app.py
```

或者在代码里：

```python
import cProfile

cProfile.run("main()", sort="cumtime")
```

看 `cumtime`（累计时间）找最大的块，再看 `ncalls` 判断是「调用次数多」还是「单次慢」。

## py-spy：看线上

```bash
pip install py-spy
py-spy top --pid 12345
py-spy dump --pid 12345
```

不用改代码、不用重启，适合排查生产环境卡死。容器里需要 `SYS_PTRACE` 权限。

## tracemalloc：找内存

```python
import tracemalloc

tracemalloc.start()
run()
snapshot = tracemalloc.take_snapshot()
for stat in snapshot.statistics("lineno")[:10]:
    print(stat)
```

## 先看复杂度，再看常数

- O(n²) 换成 O(n)，比任何微优化都有效
- 数据库 N+1 查询，比 Python 层的技巧重要得多
- 一次网络往返，比一万次列表操作还贵

## lru_cache

```python
from functools import lru_cache

@lru_cache(maxsize=1024)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)
```

只适用于纯函数、参数可哈希、结果可复用。带副作用的函数加缓存会制造 bug。

## 优化顺序

1. 确认瓶颈（profile）
2. 改算法或数据结构
3. 减少 I/O 与数据库往返
4. 批量处理
5. 最后才考虑微优化与 C 扩展
