## 本节目标

建立部署的整体模型：代码、运行时、配置、数据分别放在哪，谁负责什么。

## 最小可用架构

```
浏览器
  │ 443 (TLS)
  ▼
Nginx ── TLS 终止 / 静态文件 / 反向代理
  │ 8000 (HTTP，仅内网)
  ▼
FastAPI (uvicorn)
  │ 5432
  ▼
PostgreSQL
```

各组件职责：

| 组件 | 职责 | 不要做 |
|---|---|---|
| Nginx | TLS、静态文件、限流、转发 | 不要写业务逻辑 |
| 应用 | 业务逻辑、鉴权 | 不要直接对公网暴露 |
| 数据库 | 持久化 | 不要把 5432 暴露到公网 |
| 操作系统 | 防火墙、备份、监控 | 不要用 root 跑应用 |

## 三种部署形态

| 形态 | 适合 | 代价 |
|---|---|---|
| 裸机 / 虚拟机 + 系统 Python | 学习、临时验证 | 环境漂移，换机器就崩 |
| 虚拟机 + Docker Compose | 小项目、个人产品 | 要自己维护服务器 |
| 托管平台（Render / Railway / Fly） | 快速上线 | 成本与平台锁定 |

这个阶段练第二种：一台 VPS + Docker Compose。它足够支撑真实的小产品，也能让你看清每一层。

## 12-Factor 里最要紧的四条

1. **配置放在环境变量**，不写进代码或镜像
2. **日志写到 stdout / stderr**，由平台收集，不自己管理文件
3. **进程无状态**，会话与上传文件放数据库或对象存储
4. **通过端口绑定提供服务**，不依赖外部服务器

## 上线不是终点

```
开发 → 构建 → 部署 → 观测 → 回滚
```

没有观测和回滚方案的部署，只是把代码放到服务器上赌运气。
