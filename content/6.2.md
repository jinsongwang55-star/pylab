## 本节目标

用一份 `compose.yml` 把应用、数据库、Nginx 串起来，一条命令启动整套环境。

## 完整示例

```yaml
services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER}"]
      interval: 5s
      timeout: 3s
      retries: 10
    restart: unless-stopped

  api:
    build: .
    env_file: .env
    depends_on:
      db:
        condition: service_healthy
    expose:
      - "8000"
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "python", "-c", "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8000/health')"]
      interval: 10s
      timeout: 3s
      retries: 5

  nginx:
    image: nginx:1.27-alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - ./certbot/conf:/etc/letsencrypt:ro
      - ./certbot/www:/var/www/certbot:ro
    depends_on:
      - api
    restart: unless-stopped

volumes:
  pgdata:
```

## 关键点

| 配置 | 作用 |
|---|---|
| `depends_on: condition: service_healthy` | 等数据库真正可用再启动 API，而不是只要容器起来就走 |
| `expose` 而不是 `ports` | API 只在内网可达，公网只能经 Nginx |
| `volumes: pgdata` | 数据库数据落在命名卷，容器删了数据还在 |
| `restart: unless-stopped` | 进程崩溃或服务器重启后自动拉起 |
| `env_file: .env` | 配置不写进镜像 |

## 环境变量

`.env`（不提交）：

```bash
POSTGRES_USER=blog
POSTGRES_PASSWORD=换成强随机密码
POSTGRES_DB=blog
DATABASE_URL=postgresql+asyncpg://blog:密码@db:5432/blog
SECRET_KEY=换成 32 字节以上的随机串
```

`.env.example`（提交，值留空）：

```bash
POSTGRES_USER=
POSTGRES_PASSWORD=
POSTGRES_DB=
DATABASE_URL=
SECRET_KEY=
```

注意连接串里的主机名是 **`db`**，也就是 compose 的服务名。容器之间用服务名互相解析，不是 `localhost`。

## 常用命令

```bash
docker compose config          # 校验并展开变量，先跑这个
docker compose build
docker compose up -d
docker compose ps
docker compose logs -f api
docker compose exec api sh
docker compose down             # 停止并删除容器，保留卷
docker compose down -v          # 连数据卷一起删，慎用
```

## 数据库迁移

迁移是一次性任务，不要塞进应用的启动脚本：

```bash
docker compose run --rm api alembic upgrade head
```

如果多个副本同时启动，把迁移放在部署流程里单独执行一次，避免并发迁移。

## 备份与恢复

```bash
docker compose exec -T db pg_dump -U blog blog > backup-$(date +%F).sql
cat backup-2026-11-09.sql | docker compose exec -T db psql -U blog blog
```

备份文件不要只留在同一台机器上。没有验证过恢复的备份等于没有备份。
