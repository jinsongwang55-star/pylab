## 本节目标

把服务安全地暴露到公网：反向代理、TLS 证书、防火墙，以及出问题时怎么查。

## Nginx 反向代理

```nginx
upstream api {
    server api:8000;
}

server {
    listen 80;
    server_name example.com;

    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }

    location / {
        return 301 https://$host$request_uri;
    }
}

server {
    listen 443 ssl;
    http2 on;
    server_name example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    client_max_body_size 10m;

    location / {
        proxy_pass http://api;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 30s;
    }
}
```

三个转发头必须给：

- `X-Real-IP`：否则应用日志里全是 Nginx 的内网 IP
- `X-Forwarded-For`：多级代理时保留真实来源
- `X-Forwarded-Proto`：否则应用以为自己跑在 HTTP 上，可能生成错误的跳转链接

FastAPI 侧要信任这些头，否则拿到的 `request.client.host` 还是代理地址。

## 申请证书

用 Certbot 的 webroot 模式，不需要停 Nginx：

```bash
docker run --rm \
  -v "$PWD/certbot/conf:/etc/letsencrypt" \
  -v "$PWD/certbot/www:/var/www/certbot" \
  certbot/certbot certonly --webroot -w /var/www/certbot \
  -d example.com --email you@example.com --agree-tos --no-eff-email
```

续期与重载：

```bash
docker run --rm \
  -v "$PWD/certbot/conf:/etc/letsencrypt" \
  -v "$PWD/certbot/www:/var/www/certbot" \
  certbot/certbot renew

docker compose exec nginx nginx -s reload
```

把这两条写进宿主机的 cron，每天跑一次。证书 90 天有效，别等到过期。

不想手动管证书，可以用 Caddy 替代 Nginx，它会自动签发与续期。

## 防火墙

```bash
ufw default deny incoming
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
```

只开 22、80、443。数据库与应用端口一律不对外。

## 故障排查表

| 现象 | 常见原因 | 排查 |
|---|---|---|
| 502 Bad Gateway | api 容器没起来 / 端口不对 | `docker compose ps`、`docker compose logs api` |
| 504 Gateway Timeout | 应用处理太慢，超过 `proxy_read_timeout` | 看应用日志与慢查询 |
| 413 Request Entity Too Large | 上传超过 `client_max_body_size` | 调整该值 |
| 连接数据库被拒 | 用了 `localhost` 或密码错 | 连接串主机应为 `db`；`docker compose logs db` |
| 容器反复重启 | 启动命令失败 / 健康检查失败 | `docker compose logs --tail=100 api` |
| 静态页面正常、接口 404 | Nginx `location` 写错 | `docker compose exec nginx nginx -T` |
| HTTPS 证书过期 | 续期任务没跑 | `certbot certificates` |
| 日志时间不对 | 容器时区是 UTC | 设置 `TZ=Asia/Shanghai` |
| 权限拒绝（数据库卷） | uid 不匹配 | 不要随便 `chown -R 777`，查镜像文档 |

## 发布与回滚

```bash
# 发布
docker compose build api
docker compose up -d --no-deps api

# 观察
docker compose logs -f --tail=100 api

# 回滚：镜像打版本标签，切回上一个
docker compose stop api
docker run -d --name api-old ... blog-api:0.0.9
```

更稳的做法是始终给镜像打不可变版本标签，回滚只是改回标签再 `up -d`。用 `latest` 的团队，出事时往往不知道上一个版本是什么。
